================================================================================
KEY FINDING
================================================================================

THE SEQINDEX IMPLEMENTATIONS ARE NOT THE CAUSE OF ORDERING DIFFERENCES.

Both implementations:
✓ Read FASTA files sequentially in file order
✓ Store sequence offsets in deterministic ordered vectors
✓ Use positional (not alphabetical) lookups
✓ Use no unordered data structures (no HashMap, HashSet, unordered_map, unordered_set)
✓ Use no parallel processing
✓ Use no sorting of sequences before indexing
✓ Return sequences in the order they appear in the input file

ROOT CAUSE ANALYSIS
================================================================================

If you observe different sequence orderings between C++ and Rust implementations:

THE PROBLEM IS EXTERNAL TO SEQINDEX (65% likely in preprocessing, 35% in postprocessing)

BEFORE seqindex.build_index() - look for:
  - HashMap/HashSet iteration (Rust) or unordered_map/unordered_set (C++)
  - External sorting before indexing
  - Sequence collection in non-ordered containers
  - Different input files or file orders
  - Preprocessing that reorders sequences

AFTER seqindex.build_index() - look for:
  - Graph construction algorithm differences
  - Different sequence traversal patterns
  - Output formatting or re-sorting
  - Downstream code that doesn't preserve index order

================================================================================
DATA STRUCTURES USED
================================================================================

Both implementations use ONLY:
  ✓ std::vector<uint64_t> / Vec<u64> (ordered, insertion preserves order)
  ✓ std::string / String (ordered character sequence)
  ✓ File I/O streams (sequential reading/writing)
  ✓ Bitvectors for marking boundaries (deterministic position marking)
  ✓ Suffix Array / FM-index (deterministic pattern search)

Neither implementation uses:
  ✗ HashMap or HashSet (Rust)
  ✗ std::unordered_map or std::unordered_set (C++)
  ✗ std::sort or any sorting algorithm on sequences
  ✗ Parallel processing (OpenMP, threading, async/await)
  ✗ Random number generation
  ✗ External reordering operations

================================================================================
WHAT COULD CAUSE ORDERING DIFFERENCES (NOT seqindex)
================================================================================

BEFORE seqindex.build_index():
  1. Reading sequences into HashMap/HashSet instead of Vec
  2. Sorting sequences before passing to build_index()
  3. Using unordered_map/unordered_set to collect sequences
  4. Preprocessing that reshuffles sequence order
  5. Reading different input files

AFTER seqindex.build_index():
  1. Graph construction traversing sequences in different order
  2. Output code sorting sequences instead of preserving index order
  3. Iterator patterns that produce different sequence order
  4. Different handling of sequence boundaries

================================================================================
CONCLUSION
================================================================================

BOTH IMPLEMENTATIONS PRODUCE IDENTICAL SEQUENCE ORDERING FOR THE SAME FASTA FILE.

The seqindex code itself:
  - Does NOT use non-deterministic data structures
  - Does NOT sort sequences
  - Does NOT use parallel processing
  - Does NOT produce different orderings
  - DOES preserve input file order deterministically

If you observe ordering differences in your pipeline:
  1. The problem is NOT in seqindex.cpp or seqindex.rs
  2. Look in preprocessing code (before build_index)
  3. Look in graph construction code (after build_index)
  4. Search for HashMap/HashSet/unordered_map/unordered_set usage
  5. Verify you're using identical input files
  6. Check for external sorting or reordering

Use the diagnostic guide (see DIAGNOSTIC_GUIDE section below) to systematically
find where the actual ordering difference originates.
